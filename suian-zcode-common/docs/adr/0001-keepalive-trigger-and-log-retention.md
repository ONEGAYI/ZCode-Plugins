# ADR 0001：网关周期看护触发器与按启动批次日志留存

- 状态：已接受
- 日期：2026-10-25
- 关联规格：[keepalive-log-retention-spec.md](../keepalive-log-retention-spec.md)

## 背景

10/24 22:43 公共网关被外部终止（任务退出码 1）后无人拉起，约 24 小时内依赖网关的 RPC 链路全部失效。计划任务仅登录触发；注册自带的失败重试（`RestartCount 3 / 1min`）在该次故障中未兜住（已观察到的行为，未深挖根因）。同时网关日志（`gateway.out.log` / `gateway.error.log`）固定文件名、每次启动截断覆盖且无版本上下文；两族 jsonl 事件日志（hook、toast-action）只增不减。

## 决策

1. **看护拉起用"单任务 + 周期重复触发器"，不新增看护任务**：现有任务在 AtLogOn 之外加"每 N 分钟重复（默认 30，setup 可配 5–1440 并记入 config.json）"的触发器。幂等由两层保证——任务层 `MultipleInstances IgnoreNew`，启动器层拉起前健康探测（健康即退出，fail-open）。
2. **网关日志按启动批次命名**：`DataDir/logs/gateway-<yyyyMMdd-HHmmss>.{out,error}.log`，一对文件对应一次启动；启动横幅升级为自描述 JSON（时间、模式、端口、协议版本、build、node、pid）作为 out.log 首行。
3. **留存统一 7×24 小时滚动窗口，判定依据文件名时间戳**：启动批次日志由启动器在拉起前清理；jsonl 按天滚动（`<族>-<yyyyMMdd>.log.jsonl`）、每条事件行内嵌版本字段、写入点自清理。
4. **存量升级走被动路径**：重跑 `setup.ps1 Install/Restart` 时由触发器形状比对自动重注册为新形状；不给 depcheck 增加检测职责。

## 后果

- 网关非正常退出后最坏 30 分钟自愈；上次故障场景（进程整体死亡）被完全覆盖。
- 任意日志文件或单行脱离原目录后仍可独立溯源启动时间与版本。
- 日志总体量受 7 天窗口约束；极端重启风暴下不再无限累积（估算最坏 670 对 KB 级文件，不设大小上限）。
- 新旧布局切换一次性发生：旧 `gateway.out.log`、旧单文件 jsonl 在首次新写入时删除（历史内容已被历次启动覆盖，无保留价值）。
- 僵尸进程（存活但不监听）仍需手动 Restart——本期明确不引入主动杀进程语义。

## 备选方案（已否决）

- **独立看护任务**（每 30 分钟探测 + 按需拉主任务）：多一个任务、Remove/回退路径双份管理，被周期触发器 + IgnoreNew 的零成本幂等取代。
- **伴随 meta 文件承载启动上下文**：多一族文件与清理规则，error.log 仍无内容上下文；横幅进 stdout 更自然。
- **jsonl 文件级头行自包含**：行被单独摘出（如贴进 issue）即丢失版本；行级内嵌字段成本仅每行数字节。
- **depcheck 检测任务形状并 Toast 提醒**：扩大 depcheck 职责边界，既有"插件更新后重跑 setup"路径已足够。
- **单文件 jsonl 定期截断**：截断有并发与行边界问题，按天滚动天然规避。
