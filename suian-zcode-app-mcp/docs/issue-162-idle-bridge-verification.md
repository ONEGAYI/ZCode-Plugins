# #162：空闲后的旧 Host 桥复用

日期：2026-10-23。关联 [Issue #162](https://github.com/ONEGAYI/ZCode-Plugins/issues/162)。本记录属于隔离开发验证，未替代日常安装、官方在线 relay 或真实手机验收。

## 已复现的失败路径

**Desktop 已结束旧桥，网关仍复用旧身份**。新增诊断把外层 `gateway_rpc_protocol_error` 收窄到 `desktop_payload` 阶段的 `bridge-degraded`，底层原因是 `terminal-owner-ended`。这是有效的桥生命周期通知，本次没有观察到字节损坏或帧序号缺口。

隔离的 Desktop 3.16.3.8992 包内，`scheduleMobileDisconnectGrace` 的计时常量是 `uN=3e3`。宽限期结束后调用 `endTerminalOwner`，释放桥资源，并把旧身份的 `bridge-degraded` 存入 `pendingBridgeInvalidation`。再次配对时，这条通知才到达网关。

原网关只在错误或 Desktop 断开时清理物理桥。最后一个本地客户端退出后，旧桥仍留在 broker 中。空闲后重新附着时，迟到通知命中这个旧身份，导致新客户端以协议错误退出；记录中的客户端附着失败耗时为 4–7 ms。之后还出现无人等待的桥初始化超时。

这条路径能产生 Issue 中相同的外层错误。日常旧网关缺少底层诊断，不能据此断言 Issue 中或用户此前的每次失败都由同一原因造成。

## 隔离边界与重复方法

- 使用 Desktop 3.16.3.8992 的独立真实副本、独立 HOME、用户数据、会话数据、storage 和工作区。
- 副本采用仓库已有精确档案的 v3 补丁，短路登录／HTTP 注册并连接回环网关；未改 RPC 传输实现。
- 网关和客户端来自本次构建的 common 0.7.2 发布目录。relay V2 使用回环 WebSocket 夹具，响应官方配对消息；不使用真实账户或官方网络。
- 每次调用都执行 `connectHost` → 真实 Host 的 `model-selection.getView` → 关闭连接。未调用模型、改名、创建会话或发信。
- 每轮包含连续 100 次、5 路并发共 100 次、间隔 2 秒的 10 次、间隔 12 秒的 6 次，合计 216 次。长间隔专门跨过 Desktop 的失配宽限期。
- Desktop 副本会改写当前用户的协议和右键菜单。运行前备份 5 个值，就绪后及退出后恢复并逐项核对；日常应用包、配置和网关不变。

首轮原始报告保留在工作树忽略目录 `.scratch/issue-162/`，包括 `native-relay.log`、`native-lab/reports/attempts-relay.json`、补丁身份核对和构建日志。日志首次运行即落盘，并追加命令退出码；原始红灯记录没有覆盖。

## 最小修复

1. 最后一个本地或手机使用者退出时，先取消该使用者的 RPC；内部会话归属查询等请求也结束后，再释放物理桥。下一次附着使用新身份；仍在线的多个使用者继续共用一个桥。
2. 消费已退役桥的迟到 `bridge-degraded`，不让它破坏新桥，也不把网关物理身份转给手机。手机远端工作区的透传例外保留。
3. 不重试业务请求；已经提交的写操作仍保留结果可能未知的语义。

代价是完全空闲后下次附着要重新建桥。没有引入延时重试、保活或 Desktop 补丁变更。
