# 每会话工件状态独立持久化，自动投影按模型请求生成

**状态**：设计与实现方案已整体确认并开票，2026-10-10；尚未实现。

## 背景

工件区用于持续提供当前工作相关的 PR、父子会话和关键文档/文件引用。将每次状态快照追加到聊天历史会保留旧状态，也会占用越来越多的上下文。

## 决定

- 每个会话独立持有工件区；父子会话各自维护，通过引用关联。
- 工件真实状态独立持久化，支持重启恢复；自动投影不写入 ZCode 聊天历史，也不提交 Git。
- 每个实际模型请求，包括工具执行后的续跑请求，都读取最新状态并附加一份尾部投影。set 成功后，下一次模型请求必须看到新状态。
- 唯一性只约束自动投影。正常聊天、set 参数和 get 结果仍按原有历史机制保留；工具回执保持简短。
- 使用独立插件，不修改 ZCode。若发行版缺少满足目标的请求级入口，则将上游支持列为前置依赖，不放宽目标或修改研究用 submodule。
- Agent 根据用途管理引用的生命周期；服务限制条目数和投影体积。超限时明确拒绝写入并要求清理，不静默丢弃条目。
- 条目数上限为 20；生成后的完整投影最多 12000 个 Unicode 字符，字符数不等于 token 数。
- set 只提交变动条目，支持批量 upsert（新增或更新引用）与 remove（移除引用）。检查 revision，成功回执只返回新版本与变动数量，避免重发整个工件区。
- 分叉时复制父会话工件作为子会话独立初始状态，之后互不自动同步。普通新会话从空集合开始；恢复和压缩保留自身状态，回退聊天不自动回滚工件。
- 外挂只读面板作为可选后续票，首版核心不依赖面板完成。
- 在现有 suian-zcode-app-mcp 中新增 get_artifacts/set_artifacts；两者仅操作宿主上下文确定的当前会话。
- 条目仅含 kind/ref/label/purpose，kind 固定为 pr、session、file、link。按 ref 更新或移除；父子会话和文档用途写入 purpose。
- 临时投影处于整个模型请求的 messages 数组末端，不修改真实用户消息正文来保存投影。

## 影响与取舍

工件状态与聊天历史分离，可以重建最新投影并避免重复自动快照。代价是宿主必须提供请求级临时投影能力：仅有 UserPromptSubmit 的 additionalContext 不能视为能力已经满足，需验证实际请求、运行时历史和聊天存储三条路径。

增量 set 减少重复工具输入，但每个模型请求仍需要最新投影，存在上下文成本。分叉复制还需要可靠的父子身份及分叉时点；不能用子会话首次启动时的父会话最新状态冒充分叉时快照。

保存或移除的是工件引用；不由此推导对对应 PR、会话或文件的操作授权。已确认的设计与方案对应 [工件区规格](../artifact-zone-spec.md)，实际编号与依赖见 [开票索引](../artifact-zone-tickets.md)。[当前发行版核验](../artifact-host-capabilities.md) 已完成，正式插件能力不足；本决定保留目标契约，实施等待上游支持。
