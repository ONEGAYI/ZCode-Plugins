# 更新记录

本文件记录 suian-zcode-app-mcp 的用户可感知变化，版本独立于 common 和自动命名插件。

## [Unreleased]

## [0.11.1] - 2026-10-23

补齐会话操作失败的分层诊断，配合 common 0.7.3 定位间歇性 Host 附着错误。

### Bug 修复

**跨层错误回执（会话工具、工件详情与 GLM）（[#162](https://github.com/ONEGAYI/ZCode-Plugins/issues/162)）**

- 工具结果保留网关阶段、原因码和安全诊断 ID，包括包装错误与部分成功中的失败。
- stderr 记录带时间戳的受控工具失败日志，不复制工具参数、对话正文或异常中的任意文本。
- 工具参数、写入语义及失败后不自动重试的行为保持。

## [0.11.0] - 2026-10-20

发布包自带运行依赖，使用独立共享的 common 0.5.0；补充项目查询与明确的项目会话创建方式。

### 新功能

**发布包与独立安装（#124）**

- stdio、工件 Hook、侧栏资源及第三方许可随包交付，安装后不再运行 npm 或创建公共包链接。
- 从实际安装记录加载共享 common，配置与状态仍在版本缓存外；安装检查支持显式清单路径。

**项目查询与会话创建（#126、#127）**

- 新增只读 `list_projects`，按项目筛选新会话的归属。
- `start_session` 可用 `project_id` 选择项目主根，或用 `workspace_path` 选择工作目录，两者二选一；创建后核对项目与目录。

### 变更

- 定时任务工具更名为 `set_cron_enabled`、`list_crons`，旧名称不再提供；参数 `automation_id`、返回字段 `automationId` 和已有任务 ID 保持不变（#123）。
- `start_session` 的项目与目录参数不接受 `null`；省略可选参数时仍按既有继承规则处理（#127）。

> **升级注意**：调用方需更新 Cron 工具名，并配套更新 common 至 0.5.0；通过新缓存中的 setup 核对配置与入口，保留原有授权和暂停状态。

> **分发与验证范围**：本版代码和 ZIP 的准备不代表正式市场已切换。公开 Release 下载核验与市场切换完成后才可按新方式更新；真实 Desktop、系统通知和模型操作的未验范围保留，见 #121。

## [0.8.0] - 2026-10-18

新增定时任务管理能力：查询、暂停/恢复，以及定时任务派发轮内恢复官方 Cron 工具调用的唤醒语法糖。

### 新增

**`list_automations` 只读工具**

- 直读本机 tasks-index 的 automations 表列出定时任务，缺省全量，`workspace_path` / `workspace_key` 可选过滤；空表返回空列表不报错。

**`set_automation_enabled` 启停工具**

- `enabled:false` 暂停调度（任务保留不删）、`true` 恢复，经 `zcode-agent` 通道直达官方定时任务服务；目标工作区须已在网关连接的 Desktop 打开。
- 官方写入对零行更新（任务不存在或工作区不匹配）静默成功，本工具写后同 scope 读回确认：未找到或状态不符返回明确结构化错误，已处于目标状态视为幂等确认。

**`reset_cron_tools_visibility` 唤醒语法糖**

- 面向定时任务派发轮：官方在该轮剥离 Cron 写工具（能看见但调不动），本工具向当前会话投递 queue 自发消息并要求收到回执后立即结束本轮，下一轮（人工轮）官方 Cron 工具恢复。
- 目标固定为本次 MCP 请求的发起会话，不接受手填；入参仅可选 `instruction`。

### 其他改进

- 新增 skills/automations 技能域文档，根 SKILL.md 登记路由；工具描述按 writing-for-agents 纪律只写模型调用所需信息。
- 普通客户端公开工具 16 → 19（MCP Apps 客户端另有 2 个面板专用工具）。
- 原生清单、包元信息、锁文件根版本和市场条目同步为 `0.8.0`，运行时继续读取包版本。

> **验证范围**：198 项回归通过（隔离 stub 覆盖 RPC 契约与 MCP 契约）；设计依据的本机实测证据见 `docs/automation-tools-spec.md`。真实 Host 网关端到端验收待后续执行。

- 原生清单、包元信息、锁文件根版本和市场条目同步为 `0.7.2`，运行时继续读取包版本。

> **兼容范围**：本次面向当前 ZCode，仅读取文本 JSON 的旧客户端不在兼容范围；完整数据应读取 `structuredContent`。

> **验证范围**：190 项回归通过；当前 ZCode 3.15.3.8237 产物离线重放确认完整正文由两份降为一份，Chromium＋真实 MCP＋隔离 SQLite 的侧栏验证通过。未替换用户安装缓存，实际 Desktop 更新后的端到端验收仍待执行。

## [0.7.0] - 2026-10-16

新增会话自省能力：发起 MCP 请求的会话可以直接读回自己的 ID、标题、权限模式与工作区信息，不再需要间接推断或手填标识。

### 新特性

**新增 `get_current_session` 只读自省工具**

- 识别本次 MCP 请求的发起会话并回读本机信息：session_id、CLI 库标题与权限模式、工作区路径、任务索引标题与未删除匹配行；来源识别链路与创建/发信一致（请求上下文优先，缺失时按 trace_id 与工具名查本地调用记录）。
- 只读本机双库、不连接网关；会话未落库（子代理上下文、deferPersistence）时字段为空不报错；来源未知按错误回报，冲突时给出候选 ID。

## [0.6.0] - 2026-10-15

工件面板全面增强：新增议题分类、PR/议题实时状态与行尾数字、文件三态图标和"用文件资源管理器打开"；会话工具新增置顶管理，归档读回更可靠。

### 新特性

**工件分类新增"议题"（#67）**

- 工件登记支持 GitHub 议题链接（校验规则与 PR、链接一致），注入简表的每类保底名额自动覆盖（每类最新 3 条、总额与字符预算不变）。
- 面板新增"议题"分组（位于 PR 之后）与专属图标，详情页超链接行为与 PR 一致。

**PR/议题实时状态与行尾数字（#68 #70）**

- PR 条目按实时状态显示图标（开放/草稿/冲突/已合并/已关闭），行尾右对齐显示相对主分支的增删行数（绿 +、红 -）；议题条目显示开放/已关闭图标与行尾评论数（气泡 + 数字）；详情页同步显示。
- 状态由插件在本机经 gh 拉取，仅在面板刷新时进行，模型侧 `get_artifacts` 行为不变、不产生网络请求；拉取超时沿用旧数据并以黄色钟表提示原因，出错回退默认图标且不显示数字。
- PR 与议题在同一次面板刷新中共用一次请求，互不影响对方的降级状态。

**文件三态图标与资源管理器打开（#69 #71）**

- 文件条目读取时实时探测：文件夹与文件显示不同图标，路径已删除时按原图标样式灰化（仅"路径不存在"判定缺失，权限等异常不误判）。
- 文件/文件夹详情页新增"用文件资源管理器打开"：文件打开所在目录并选中，文件夹直接打开；操作仅接受当前会话已登记的文件工件，缺失条目按钮灰化，失败在面板行内回报。

**会话置顶管理（#61 #62）**

- 新增 pin_session、unpin_session 与 list_pinned_sessions 工具：置顶经公共网关写入并从本机索引读回确认，与归档互不排斥。
- list_sessions 置顶优先，置顶内部与非置顶各自按更新时间排序。

### Bug 修复

- 归档与复原的读回确认改用 task_id 精确查询，列表截断不再导致"未确认"误报（#63）。

### 其他改进

- 修复审查发现的问题：状态缓存按拉取规格隔离同 URL 的 PR 与议题快照；文件探测与打开预检纳入超时预算，网络盘悬挂不再拖住读取；状态通道整次失败时面板回退默认图标（下次成功即恢复）；迟到的打开回执不再污染其它条目详情（#72）。
- 市场、插件清单、包元信息和锁文件根版本同步为 `0.6.0`；运行时继续读取包版本。

## [0.5.0] - 2026-10-15

打开的工件面板在 `set_artifacts` 增删改后自动刷新，不再需要手动点"刷新"或重开面板。

### 新特性

**工件面板实时刷新（资源订阅）**

- server 宣告 `resources.subscribe` 能力并注册变更信号资源 `suian-artifacts://current`；工件实际写入（增删改、会话关联建链）且事务提交成功后向已订阅方推送 `notifications/resources/updated`，内容完全相同的 upsert 不推送，回滚不推送。
- 面板经 `window.zcode` 桥（ZCode 3.15+ 的 `zcode/resourceSubscribe` 扩展）订阅信号：到达时自动重拉列表与停留中的详情页，数据仍经只读的 `get_artifacts` 工具按当前会话拉取——不产生模型请求、不写聊天历史。
- 信号突发时列表与详情重拉均带合并（进行中收到新信号合并为完成后补拉一次），不放大对原 Host 的会话状态实时查询；初始化先订阅后首刷，丢信号窗口压至订阅在途毫秒级。
- 旧宿主或桥缺订阅能力时静默保持手动刷新，既有手动刷新、分页 revision 校验、主题订阅、分页续读行为不变。
- 研究依据与上游源码结论见 `docs/artifact-live-refresh-research.md`，验证证据见 `docs/artifact-live-refresh-evidence.json`（契约 6 例、回归 131/131、三轮审查修复循环）。

### 其他改进

- 市场、插件清单、包元信息和锁文件根版本同步为 `0.5.0`；运行时继续读取包版本。

## [0.4.0] - 2026-10-12

用户提交时自动注入最近工件简表，并为其他类别保留展示空间。注入裁剪不改变完整工件数据。

**提交时的工件简表（Desktop 本地会话）（#51）**

- get_artifacts 每次读取当前会话的最新列表、revision 和分类统计；set_artifacts 按 revision 校验并增量登记或移除 PR、关联会话、文件和链接。
- 工件保存在插件外置 SQLite，每会话最多 20 条、完整表示最多 12000 个 Unicode 码点；批次写入和容量检查保持原子性。
- 用户提交时注入一句及时登记的工具入口和统计，详细管理规则放在工具描述；工具回执提供更新后的统计。
- 同步 Stop Hook 保存不可变快照与断点映射，原生分叉按所选历史断点继承独立副本；缺快照时显示 snapshot_missing，子会话仍能继续管理工件。

**原生只读工件侧栏（Desktop 本地会话）（#31、#37）**

- 在侧边面板的“打开标签页”中选择“工件”，查看完整条目、revision 和统计，刷新时读取最新状态，无需模型参与。
- 按 ZCode 应用版本与 MCP Apps 能力提供页面资源；旧版继续保留工件工具和提交摘要。
