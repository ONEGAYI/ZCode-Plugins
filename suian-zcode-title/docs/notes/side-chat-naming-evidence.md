# 侧边聊天跳过自动命名

2026-11-20 在隔离 Windows Desktop 3.19.0.10774 验证。两轮对照使用相同的 common 0.10.4 网关和本地受控模型；仅替换 title 0.4.3 的插件构建。

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 三个独立的侧边辅助对话 | 正常回复；三次 Stop 都在网关 `session_lookup` 报 `gateway_rpc_failed` | 正常回复；三次 Stop 都记录 `skipped_side_chat`，未调用命名模型，标题不变 |
| 同一主聊天的两轮 | 两次成功改名 | 两次成功改名，并经原 Host 与双库读回复核 |
| Windows 通知 | 第一轮侧聊失败后，系统记录一条「ZCode 自动命名暂停」 | 测试窗口内未新增命名插件通知，隔离通知冷却记录未创建 |

辅助对话在会话库标记为 `selection_side_chat`，有会话内容和 Stop 事件，但不进入主任务索引。命名插件只跳过这个类型，不使用索引缺行或存在父会话作为判断条件。

CLI 回归用例在修复前返回 `failed`，修复后侧聊返回 `skipped_side_chat` 且未访问网关。共用同一模拟错误的普通分叉仍返回 `gateway_rpc_failed`，保留告警路径。命名后端、历史读取和 CLI 共 35 项相关测试通过。
