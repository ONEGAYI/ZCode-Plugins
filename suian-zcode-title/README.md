# suian-zcode-title

让 ZCode 的会话标题跟上你正在做的事情。每轮对话结束后，自动参考最近三轮内容更新标题，会话再多，也更容易找回。

## 一眼看出每个会话在做什么

| 原来的标题 | 自动命名后 |
| --- | --- |
| C:/Users/…/handoff-zcode-title-202610…（被截断的临时文件路径） | 🧩 远控 Hook 插件｜授权失效排查 |
| 检查主树脏文件决定保留或推送 | 🧩 Git 工作树｜脏文件清理 |
| 帮我看看这个报错 | 🧪 发布流水线｜超时排查 |

标题统一为「类别 emoji + 对象｜目标」，先说处理的对象，再说要完成的事：

- 对象在前：模块名、工具名或内容主题，不以"修复""优化"这类动作开头
- 类别固定十种：🎬 内容制作、🧩 工具开发、🧪 工程验证、📋 项目协作、🔎 对比调研、🎨 页面设计、📝 方法整理、📅 日程安排、⚙️ 环境配置、💬 一般讨论
- 名称稳定：补测试、提交代码这类后续动作不会改动标题，你明确转向新工作时才更新
- 跟随语言：中文对话用中文标题，英文对话用英文标题
- 由你控制：手动改过的标题不会再被自动命名覆盖，想恢复时对 ZCode 说一声即可

## 基于官方 Web 远控通道，不动你的对话

命名不往对话里插入任何消息，也不直接写 ZCode 的数据库：

1. Agent 按公共网关 skill 配置后台网关与 Desktop 启动变量；你在窗口开启「移动端远程控制」。插件无需取得手机链接。
2. 每轮对话结束，ZCode 的 Stop Hook 启动后台 worker，通过公共网关调用当前窗口 Host。
3. 后台进程用你账号里实际可用的模型（默认 GLM-5.3-Flash 低速档，可换）读最近三轮，生成标题后调用官方改名接口写回，几秒内完成并断开。

### 会不会影响手机远程控制

旧版独立 terminal 曾在实测中接管手机席位。新版统一走 [公共网关](../suian-zcode-common/SKILL.md) 本地 RPC，共享窗口 Host 的一个桥，不另占官方席位。

**已实测的共存范围**：本地工作区的 MCP 发信、改名和回复读取成功，用户确认手机无需刷新或重连仍可操作；命名插件的 probe、doctor 也通过。完整 Stop Hook 后台命名与手机同用尚未实测。并行请求、订阅和手机离线调用另有隔离契约验证，详见 [共存验证记录](../suian-zcode-app-mcp/docs/relay-gateway-coexistence.md)。

旧进程必须安全重载后才有此能力，不能只更新文件。手机正在使用远端工作区时，命名明确让位；网关或原窗口不可用时，仍按两小时冷却弹 Windows 通知，按钮复制网关排障提示词。

## 让 ZCode 帮你安装或升级

直接在 ZCode 对话里粘贴下面这段，**无需先手动克隆**。同一提示词支持首次安装和升级，由 Agent 先询问操作、检查已有安装，再获取代码。

```text
请帮我安装或升级自动命名插件 suian-zcode-title：
https://github.com/ONEGAYI/ZCode-Plugins.git

先询问我是首次安装还是升级，以及源码放在哪里。
先检查已有源码和安装位置，优先复用现有仓库；没有时再确定克隆目录。
确认后，由你克隆或更新代码。首次安装按根 README 的“代码获取范围”使用稀疏检出，
获取 suian-zcode-title、公共 suian-zcode-common 和仓库根文件，不初始化 sources 子模块。
已有仓库保留其他已安装插件的目录；更新遇到本地修改或分叉时先说明，不强制覆盖。

读取仓库中最新的 suian-zcode-title/SKILL.md，
公共层统一按 suian-zcode-common/SKILL.md 配置，复用同一网关，
保留已有授权、模型选择和其他配置。
完成后分别检查插件与网关；需要我操作界面或重启时，说明保存工作、完整退出
和从正确环境重开的方法，不要自行重启 ZCode。
```

本插件的获取范围是 **自动命名目录 + 公共层 + 仓库根文件**，可以不检出 MCP。克隆命令与已有稀疏检出的扩展方式统一见 [根 README 的代码获取范围](../README.md#代码获取范围)。如果也要安装 MCP，可使用根 README 的组合提示词，由 Agent 询问插件选择。

## 日常怎么用

装好后不需要管它。想让 ZCode 做这些事的时候直接说：

- 「暂停会话自动命名」「恢复会话自动命名」
- 「命名插件换个模型」——更换生成模型或思考档位
- 「命名插件检查一下」——分层诊断，定位到具体哪一环出问题
- 「命名通知总是弹」「通知点了没反应」——通知排障

## 状态与限制

- 命名运行已在 Windows 10/11 实测。需要 Node.js 24+ 和 sqlite3；命名模块无需 npm 依赖，公共层网关单独执行 `npm ci`。
- Stop Hook 在安装时写入，只对之后新建的会话生效；安装前已经开着的会话不会被命名。
- 网关须连接当前 ZCode 窗口；窗口关闭或远控未开启时命名不可用。旧授权密文保留兼容，不参与新版默认调用。
- 模型调用走你自己的账号，每次命名的 token 用量记录在本机，可随时查看。
